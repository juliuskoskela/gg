# Command inventory

The registry in `app/commands/registry.ts` defines stable command IDs, labels, scopes, availability reasons and guarded execution. The palette (Commands or Ctrl/⌘ K), contextual menus, relevant toolbars and native menu dispatch use these definitions. `commands/context.ts` retains the current file/hunk/bookmark/workspace operand independently of transient menu visibility. Repository and precise revision identity invalidate stale execution.

| IDs | Scope and surfaces | Behavior and limits |
| --- | --- | --- |
| `repository.undo`, `repository.redo` | Repository; palette, toolbar and shortcuts | Backend preflight supplies current eligibility and a target hint before invocation. Snapshotting can affect the eventual Undo target; Current operation explains this. Local history does not undo remote synchronization. |
| `repository.fetch`, `repository.push` | Repository; palette and desktop toolbar | Explicit remote choice; push all bookmarks is labeled accordingly. Bookmark-specific synchronization is separate. |
| `repository.refresh`, `repository.immutable` | Repository; palette | Refresh snapshots and queries authoritative current status, including external-client updates. Immutability override is explicit and does not bypass operations whose backend always requires mutable revisions. |
| `new_child`, `new_parent`, `edit`, `revert`, `duplicate`, `abandon`, `squash`, `restore`, `bookmark` | Revision; palette, revision actions, context/native menus | Availability uses the actual selection, parent count, mutation state and immutability. Edit changes the working copy; selecting only inspects. |
| `move`, `insert`, `add_parent`, `remove_parent` | Revision; command and direct-manipulation paths | Search graph destinations or enter a singleton revset; review source/destination and graph effect. Existing BinaryMutator eligibility and backend preconditions remain authoritative. |
| `context-file_history`, `context-squash`, `context-restore`, `context-move_to`, `context-copy_to` | Selected file or hunk | History, squash, restore from parent, and move; whole files also support restore into another revision. Hunk restore into another revision is disabled with an explanation because forward-copy coordinates are not supported. Cross-revision operations review their source and destination. The same ID can operate on a file or selected hunk according to its typed operand. |
| `context-external_diff`, `context-external_resolve` | Selected file | Require configured tools; resolving additionally requires a conflicted file in one mutable revision. Feedback acknowledges a launch request, not external-tool completion. |
| `context-track`, `context-untrack`, `context-push-all`, `context-push-single`, `context-fetch-all`, `context-fetch-single`, `context-rename`, `context-delete`, `context-move_to` | Bookmark or tag context | Availability follows local/remote/tracked/absent state. Labels distinguish deletion, remote forgetting and synchronization. Tags expose only supported operations. |
| `context-open`, `context-rename`, `context-forget` | Workspace context | Authoritative workspace identity limits rename to current and forget to other workspaces. Unknown identity disables restricted commands with a reason. |
| `view.history`, `view.changes`, `view.operation` and registered contributions | Workspace discovery and palette | History restores graph; Changes opens Full inspection. Current operation demonstrates the adaptive registry host; it is not a complete operation-history browser. |

Ctrl/⌘ Z and Ctrl/⌘ Shift Z invoke repository undo/redo outside text editors. Command execution rechecks availability, repository status and selection after asynchronous destination/review dialogs. Cancellation performs no mutation. The [capability ledger](capability-ledger.md) maps commands and drag alternatives to source and evidence; [validation](validation.md) states which workflows were actually replayed.
